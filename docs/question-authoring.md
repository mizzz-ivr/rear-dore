# 問題セット追加・編集ガイド

## 目的

固定問題データを、安全かつレビューしやすい差分で追加・編集するためのルールをまとめます。

問題データは日本時間の日付から選ばれるため、内容だけでなくID、公開スケジュール、保存データとの互換性にも影響します。

## 現在のデータ仕様

- 現在は15セット・75問を登録している
- 1セットは5問で構成する
- 1問は4〜5個の選択肢を持つ
- 各選択肢の`percentage`合計は100にする
- `percentage`は有限の0以上100以下とする
- 問題セットID、問題ID、選択肢IDは、それぞれ全データ内で重複させない
- ID、セット名、問題文、選択肢ラベルに空文字や空白だけの値を使わない

現在の問題データは、変更履歴を追いやすくするため複数ファイルへ分割しています。

- `lib/game.ts`: `daily-01`〜`daily-03`とローテーション定義
- `lib/extra-question-sets.ts`: `daily-04`〜`daily-07`
- `lib/additional-question-sets.ts`: `daily-08`〜`daily-10`
- `lib/question-sets-11-15.ts`: `daily-11`〜`daily-15`

実行時はすべて`questionSets`へまとめます。将来さらに増やす場合は、既存ファイルへ無制限に追記するのではなく、連番範囲が分かる新しいデータファイルへ分離してください。

選択率はMVP用の固定データです。実際の利用者回答を集計した値ではありません。実ユーザー集計へ移行する場合は、固定データと同じ意味で扱わず、データモデル・表示文言・重複回答対策を別途設計します。

## ID命名

IDは英小文字とハイフンを基本とし、意味が分かる名前にします。

```ts
{
  id: "unexpected-holiday",
  prompt: "急に学校や会社が休みになった。どう過ごす？",
  choices: [
    {
      id: "unexpected-holiday-sleep",
      label: "二度寝する",
      percentage: 44,
    },
  ],
}
```

推奨ルール:

- 問題セットID: `daily-連番-テーマ`
- 問題ID: 問題の内容を表す短い英語
- 選択肢ID: `問題ID-選択肢の意味`
- 公開後の既存IDは原則変更しない

IDを変更すると、同日進捗、プレイ履歴、練習モード、テーマコレクションの復元時に旧IDを解決できなくなる可能性があります。文言修正だけで済む場合はIDを維持します。

## 追加手順

1. 追加する連番範囲が分かる問題データファイルへ新しい問題セットを登録する
2. `lib/game.ts`の`questionSets`へ新しいデータ配列を結合する
3. 1セット5問、各4〜5選択肢を登録する
4. 各問題の選択率合計を100にする
5. 既存のIDと重複していないことを確認する
6. 実際に出題する場合だけ、新しい有効開始日とローテーションID配列を追加する
7. 切替開始日の前日・当日・1周期後を`lib/game.test.ts`へ追加する
8. 問題周期と7日ミッション周期の最小公倍数について、`lib/rotation-compatibility.test.ts`で全組み合わせを確認する
9. 次の品質チェックを実行する

```bash
npm run lint
npm run typecheck
npm run test
npm run build
```

`npm run test`では`validateQuestionSets`が全問題データを検証します。失敗時は次のような対象パスが表示されます。

```text
questionSets[1].questions[3].choices
questionSets[6].questions[0].choices[4].percentage
```

### 問題データ追加と公開スケジュールを分離する

`questionSets.length`や問題データの配列順は、ローテーション計算に使用しません。そのため、問題データを追加しただけで既存の日付対応が変わることはありません。

ただし、新しいセットを実際に出題対象へ加える場合は、既存のローテーション配列へ直接挿入しないでください。公開済み・予定済みの日付対応が変わる可能性があります。

推奨手順は、次の切替日を決めて新しいローテーション定義を追加する方式です。

- 既存ローテーションの開始日とID配列は変更しない
- 新しい有効開始日を追加する
- 新開始日の前日・当日・1周期後をテストする
- 可能なら切替当日は旧方式と同じ問題セットIDにして境界を滑らかにする
- 切替当日に既存進捗がある可能性を考慮する
- デイリーミッションとの全組み合わせが達成可能か確認する

## レビュー観点

### 必須

- IDが一意で、既存IDを不用意に変更していない
- 1セット5問、1問4〜5選択肢になっている
- 選択率合計が100になっている
- レア度の境界を意図している
- 問題文と選択肢が重複・矛盾していない
- 特定個人への攻撃、差別、危険行為の推奨を含まない
- 回答前に分布を推測できる表現を過度に入れていない
- ローテーションを変更する場合、既存日付の対応を変えていない
- 切替境界を単体テストしている
- 対応するデイリーミッションが理論上達成可能である

### 確認推奨

- モバイル幅で問題文と選択肢が長すぎない
- 4〜5個の選択肢が意味の異なる選択肢になっている
- 最少選択率の選択肢が不自然に正解扱いされない
- 毎日遊んだ際にテーマや表現が単調にならない
- UR・SSR・SRなどの選択肢が特定セットに偏りすぎていない

## 対象外

現在の検証は構造と数値の整合性を確認するものです。次は自動判定しません。

- 問題内容の面白さ
- 選択率の妥当性
- 誤字脱字
- 法務・倫理上の最終判断
- 実ユーザー回答との一致

これらはPRレビューと公開前の実画面確認で判断します。
