# 問題セット追加・編集ガイド

## 目的

`lib/game.ts`の固定問題データを、安全かつレビューしやすい差分で追加・編集するためのルールをまとめます。

問題データは日本時間の日付から選ばれるため、内容だけでなく配列順・ID・保存データとの互換性にも影響します。

## 現在のデータ仕様

- 問題セットは3件以上登録する
- 1セットは5問で構成する
- 1問は4〜5個の選択肢を持つ
- 各選択肢の`percentage`合計は100にする
- `percentage`は有限の0以上100以下とする
- 問題セットID、問題ID、選択肢IDは、それぞれ全データ内で重複させない
- ID、セット名、問題文、選択肢ラベルに空文字や空白だけの値を使わない

選択率はMVP用の固定データです。実際の利用者回答を集計した値ではありません。実ユーザー集計へ移行する場合は、固定データと同じ意味で扱わず、データモデル・表示文言・重複回答対策を別途設計します。

## ID命名

IDは英小文字とハイフンを基本とし、意味が分かる名前にします。

```ts
{
  id: "unexpected-holiday",
  prompt: "急に学校や会社が休みになった。どう過ごす？",
  choices: [
    {
      id: "unexpected-holiday-sleep",
      label: "二度寝する",
      percentage: 44,
    },
  ],
}
```

推奨ルール:

- 問題セットID: `daily-連番-テーマ`
- 問題ID: 問題の内容を表す短い英語
- 選択肢ID: `問題ID-選択肢の意味`
- 公開後の既存IDは原則変更しない

IDを変更すると、同日進捗やプレイ履歴の復元時に旧IDを解決できなくなる可能性があります。文言修正だけで済む場合はIDを維持します。

## 追加手順

1. `lib/game.ts`の`questionSets`末尾へ新しいセットを追加する
2. 5問、各4〜5選択肢を登録する
3. 各問題の選択率合計を100にする
4. 既存のIDと重複していないことを確認する
5. 次の品質チェックを実行する

```bash
npm run lint
npm run typecheck
npm run test
npm run build
```

`npm run test`では`validateQuestionSets`が全問題データを検証します。失敗時は次のような対象パスが表示されます。

```text
questionSets[1].questions[3].choices
questionSets[2].questions[0].choices[4].percentage
```

## ローテーションへの影響

`getDailyQuestionSet`は、基準日からの経過日数と`questionSets`の配列長・配列順を使って当日のセットを決定します。

そのため、本番公開後に次を行うと、過去と未来の日付に対応する問題セットが変わる可能性があります。

- 既存セットの並び替え
- 配列の途中へのセット追加
- セット削除

新しいセットは原則として配列末尾へ追加します。ただし、配列長が変わるだけでも将来日の割り当ては変わります。厳密な公開スケジュールが必要になった段階では、配列の剰余ではなく日付とセットIDを明示的に管理する方式へ移行します。

## レビュー観点

### 必須

- IDが一意で、既存IDを不用意に変更していない
- 1セット5問、1問4〜5選択肢になっている
- 選択率合計が100になっている
- レア度の境界を意図している
- 問題文と選択肢が重複・矛盾していない
- 特定個人への攻撃、差別、危険行為の推奨を含まない
- 回答前に分布を推測できる表現を過度に入れていない

### 確認推奨

- モバイル幅で問題文と選択肢が長すぎない
- 4〜5個の選択肢が意味の異なる選択肢になっている
- 最少選択率の選択肢が不自然に正解扱いされない
- 毎日遊んだ際にテーマや表現が単調にならない

## 対象外

現在の検証は構造と数値の整合性を確認するものです。次は自動判定しません。

- 問題内容の面白さ
- 選択率の妥当性
- 誤字脱字
- 法務・倫理上の最終判断
- 実ユーザー回答との一致

これらはPRレビューと公開前の実画面確認で判断します。
