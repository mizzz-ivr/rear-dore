# 問題セット追加・編集ガイド

## 目的

固定問題データを、安全かつレビューしやすい差分で追加・編集するためのルールをまとめます。

問題データは日本時間の日付から選ばれるため、内容だけでなくID、公開スケジュール、保存データとの互換性にも影響します。

## 現在のデータ仕様

- 現在は7セット・35問を登録している
- 1セットは5問で構成する
- 1問は4〜5個の選択肢を持つ
- 各選択肢の`percentage`合計は100にする
- `percentage`は有限の0以上100以下とする
- 問題セットID、問題ID、選択肢IDは、それぞれ全データ内で重複させない
- ID、セット名、問題文、選択肢ラベルに空文字や空白だけの値を使わない

既存3セットは`lib/game.ts`、追加セットは`lib/extra-question-sets.ts`で定義し、実行時は`questionSets`へまとめます。

選択率はMVP用の固定データです。実際の利用者回答を集計した値ではありません。実ユーザー集計へ移行する場合は、固定データと同じ意味で扱わず、データモデル・表示文言・重複回答対策を別途設計します。

## ID命名

IDは英小文字とハイフンを基本とし、意味が分かる名前にします。

```ts
{
  id: "unexpected-holiday",
  prompt: "急に学校や会社が休みになった。どう過ごす？",
  choices: [
    {
      id: "unexpected-holiday-sleep",
      label: "二度寝する",
      percentage: 44,
    },
  ],
}
```

推奨ルール:

- 問題セットID: `daily-連番-テーマ`
- 問題ID: 問題の内容を表す短い英語
- 選択肢ID: `問題ID-選択肢の意味`
- 公開後の既存IDは原則変更しない

IDを変更すると、同日進捗やプレイ履歴の復元時に旧IDを解決できなくなる可能性があります。文言修正だけで済む場合はIDを維持します。

## 追加手順

1. 新しい問題セットを`lib/extra-question-sets.ts`へ追加する
2. 5問、各4〜5選択肢を登録する
3. 各問題の選択率合計を100にする
4. 既存のIDと重複していないことを確認する
5. 実際に出題する場合だけ、`lib/game.ts`のローテーションID配列を別途更新する
6. 切替開始日と、その前後の日付を`lib/game.test.ts`へ追加する
7. 次の品質チェックを実行する

```bash
npm run lint
npm run typecheck
npm run test
npm run build
```

`npm run test`では`validateQuestionSets`が全問題データを検証します。失敗時は次のような対象パスが表示されます。

```text
questionSets[1].questions[3].choices
questionSets[6].questions[0].choices[4].percentage
```

## ローテーション方式

### 2026年8月7日まで

2026年7月28日を基準にした旧3セットローテーションを維持します。過去の履歴や保存済み問題セットIDとの整合性を守るため、この期間の対応は変更しません。

### 2026年8月8日以降

`STABLE_ROTATION_QUESTION_SET_IDS`へ問題セットIDを明示し、2026年8月8日を新しい基準日として7日周期で出題します。

現在の順序は次のとおりです。

1. `daily-03-choice`
2. `daily-04-digital`
3. `daily-05-food`
4. `daily-06-outing`
5. `daily-07-odd`
6. `daily-01-imagination`
7. `daily-02-everyday`

8月8日は旧方式でも`daily-03-choice`が選ばれるため、切替境界で当日の問題が変わらないようにしています。

### 問題データ追加と公開スケジュールを分離する

`questionSets.length`や配列順は、現在のローテーション計算に使用しません。そのため、問題データを追加しただけで既存の日付対応が変わることはありません。

ただし、新しいセットを実際に出題対象へ加える場合は、単純に既存の7日配列へ挿入しないでください。既存未来日の対応が変わります。

推奨手順は、次の切替日を決めて新しいローテーション定義を追加する方式です。

- 既存ローテーションの開始日とID配列は変更しない
- 新しい有効開始日を追加する
- 新開始日の前日・当日・1周期後をテストする
- 切替当日に既存進捗がある可能性を考慮する

この方式なら、将来8セット・14セットへ増やす場合も過去の対応を固定したまま拡張できます。

## レビュー観点

### 必須

- IDが一意で、既存IDを不用意に変更していない
- 1セット5問、1問4〜5選択肢になっている
- 選択率合計が100になっている
- レア度の境界を意図している
- 問題文と選択肢が重複・矛盾していない
- 特定個人への攻撃、差別、危険行為の推奨を含まない
- 回答前に分布を推測できる表現を過度に入れていない
- ローテーションを変更する場合、既存日付の対応を変えていない
- 切替境界を単体テストしている

### 確認推奨

- モバイル幅で問題文と選択肢が長すぎない
- 4〜5個の選択肢が意味の異なる選択肢になっている
- 最少選択率の選択肢が不自然に正解扱いされない
- 毎日遊んだ際にテーマや表現が単調にならない
- UR・SSR・SRなどの選択肢が特定セットに偏りすぎていない

## 対象外

現在の検証は構造と数値の整合性を確認するものです。次は自動判定しません。

- 問題内容の面白さ
- 選択率の妥当性
- 誤字脱字
- 法務・倫理上の最終判断
- 実ユーザー回答との一致

これらはPRレビューと公開前の実画面確認で判断します。
