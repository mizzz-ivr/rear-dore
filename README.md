# レアどれ？

みんなが選ばなそうな答えを選ぶ、少数派予測型のデイリーゲームです。

- 公開予定URL: https://reardore.ivrm.jp
- ホスティング: Vercel Hobby
- フレームワーク: Next.js App Router

## 開発

```bash
npm install
npm run dev
```

## 品質チェック

```bash
npm run lint
npm run typecheck
npm run test
npm run build
```

## 問題データの編集

固定問題データは現在15セット・75問です。問題データは`lib/game.ts`、`lib/extra-question-sets.ts`、`lib/additional-question-sets.ts`、`lib/question-sets-11-15.ts`へ連番範囲ごとに分け、実行時に`questionSets`へまとめます。ID命名、問題数、選択肢数、選択率合計、公開スケジュールの変更手順は[問題セット追加・編集ガイド](docs/question-authoring.md)を確認してください。

問題データの登録とローテーション定義は分離しています。新しいセットを追加しただけでは既存の日付に対応する問題は変わりません。実際に出題対象へ加える場合は、有効開始日を決めて新しいローテーション定義と境界日のテストを追加します。

`npm run test`では、現在の全問題セットを専用検証器で確認します。不正がある場合は`questionSets[1].questions[3].choices`のような対象パスとエラー内容を表示します。問題ローテーションと7日周期のデイリーミッションについても、現在の15テーマでは105日分の全組み合わせが理論上達成可能であることを検証します。

## アクセシビリティ確認

公開前にキーボードだけで次を確認します。

1. ページ先頭でTabを押し、「本文へ移動」からゲーム画面へ移動できる
2. 矢印キーで回答を選び、TabとEnterで回答確定・次の問題へ進める
3. 次の問題へ進んだ際に、新しい問題見出しへフォーカスが移る
4. 5問完了後に「今日のレア回答力」へフォーカスが移る
5. 再プレイ後に最初の問題見出しへフォーカスが戻る
6. 練習モードでテーマ選択、問題遷移、練習結果、テーマ選択への復帰時に適切な見出しへフォーカスが移る
7. テーマコレクションで発見数・バッジ進捗・未発見テーマをキーボードと支援技術で確認できる
8. 320px幅と`prefers-reduced-motion`有効時も、フォーカス表示や操作対象が見切れない

回答進捗は支援技術へ「5問中n問完了」として提供し、回答結果はレア度・選択率・獲得点だけを一度通知します。レア度グリッドの絵文字は視覚表示専用とし、読み上げにはレア度名を使用します。

問題更新カウントダウンは`role="timer"`と`aria-live="off"`を使用し、画面上の秒表示が変化してもスクリーンリーダーへ毎秒通知しません。

新規実績解除通知とテーマ初回発見通知は`role="status"`と`aria-live="polite"`を使用し、通知のためにフォーカスは移動しません。

デイリーミッションは`progressbar`として現在値・目標値を提供し、プレイ中は「挑戦中」、5問完了後は「達成」または「未達成」を文字でも表示します。回答ごとの進捗変化だけを理由にフォーカスは移動しません。

ウィークリーチャレンジとコレクションバッジも`progressbar`として現在値・目標値を提供し、達成状態は色だけに依存せず文字でも表示します。

## 環境変数

`.env.example`を`.env.local`へコピーします。

```env
NEXT_PUBLIC_SITE_URL=https://reardore.ivrm.jp
```

`NEXT_PUBLIC_SITE_URL`はHTTPまたはHTTPSのオリジンURLだけを指定します。パス、クエリ、ハッシュ、認証情報を含む値や不正な値は採用せず、`https://reardore.ivrm.jp`へフォールバックします。

## Vercelへの公開

1. Vercelで`mizzz-ivr/rear-dore`をImportする
2. Production Branchを`main`にする
3. Production環境へ`NEXT_PUBLIC_SITE_URL=https://reardore.ivrm.jp`を設定する
4. Domainsへ`reardore.ivrm.jp`を追加する
5. DNS管理側へVercelが表示するCNAMEを設定する
6. HTTPS、canonical、OGPを確認する

公開後は次のURLとレスポンスヘッダーも確認します。

- `/robots.txt`: `Host`と`Sitemap`が`https://reardore.ivrm.jp`を参照する
- `/sitemap.xml`: トップページが登録されている
- `/manifest.webmanifest`: 日本語名、開始URL、テーマ色、192px・512pxアイコンが返る
- `/pwa-icon/192`、`/pwa-icon/512`: `image/png`として表示できる
- ページの`head`: ブラウザアイコン、Apple Touch Icon、Open Graph画像、Twitter画像が登録される
- SNSデバッガー: 1200×630のブランド画像と本番canonical URLが表示される
- 全ページ: `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`、`Permissions-Policy`が付与される

アイコンとSNS画像は`ImageResponse`でコード生成し、外部画像や外部フォントには依存しません。manifestとホーム画面用画像は整備していますが、Service Worker、オフライン対応、プッシュ通知はMVP対象外です。

Content-Security-PolicyはNext.jsのスクリプトnonce設計と合わせて別タスクで導入します。HSTSはVercel側のHTTPSレスポンスで確認します。

## MVPのデータ方針

問題と回答分布はフロントエンドの固定データです。現在は15セット・75問を保持し、同じ日本時間の日付ではすべての利用者に同じ5問が表示されます。選択率は実ユーザーの集計値ではなく、MVP用の固定値です。

問題ローテーションは公開済み期間を固定するため、有効開始日ごとに明示ID配列を持ちます。

- 2026年8月7日まで: 2026年7月28日基準の旧3セットローテーション
- 2026年8月8日〜8月14日: 明示IDの7日サイクル
- 2026年8月15日〜8月24日: 10テーマを1回ずつ出題する10日サイクル
- 2026年8月25日以降: 15テーマの15日サイクル

2026年8月25日以降は、`daily-08-work-study`、`daily-11-transport`、`daily-12-shopping-money`、`daily-13-communication`、`daily-14-season-events`、`daily-15-entertainment`、`daily-09-hobbies`、`daily-10-future-tech`、`daily-03-choice`、`daily-04-digital`、`daily-05-food`、`daily-06-outing`、`daily-07-odd`、`daily-01-imagination`、`daily-02-everyday`の順で出題します。8月25日は旧10日周期でも`daily-08-work-study`になるため、切替境界当日の問題は変わりません。

ローテーションは`questionSets.length`や問題データの配列順に依存しません。そのため問題セットを追加しても、公開済み・予定済みの日付対応は自動では変化しません。将来ローテーションへ新しいセットを加える場合は、既存定義を変更せず、新しい有効開始日とローテーション定義を追加して切替境界をテストします。

全画面上部には、次の日本時間0時までの残り時間を`HH:MM:SS`で表示します。表示は1秒ごとに更新し、バックグラウンドから戻った場合やウィンドウへ再フォーカスした場合は即時再計算します。日付判定とカウントダウンは利用端末の時計を基準にするため、端末時刻がずれている場合は表示と問題切り替えにも影響します。

回答途中と総合結果は、日本時間の当日分として同一ブラウザの`localStorage`へ保存されます。保存するのは問題セットID、問題ID、選択肢IDのみで、選択率・レア度・点数は復元時に現行問題データから再計算します。

デイリーミッションは2026年8月8日を基準に、`少数派3問`、`R以上2回答`、`500点`、`少数派4問`、`SR以上1回答`、`750点`、`5問すべて少数派`の7種類をID固定の順序でローテーションします。ミッション定義の追加だけでは既存の日付対応は変わりません。進捗は当日の`answers`から毎回再計算し、専用のlocalStorageや達成履歴は作りません。15日問題周期と7日ミッション周期の全105組み合わせについて、各日の5問だけで対応ミッションを理論上達成できることをテストします。

同一ブラウザで複数タブを開いている場合は、`storage`イベントを使って回答途中・総合結果・記録削除を同期します。受信した保存値は日付、問題セット、問題順、選択肢を再検証し、不正または別日の更新は反映しません。

ページを開いたまま日本時間0時を迎えた場合は、新しい問題セットの1問目へ自動で切り替えます。バックグラウンド中に日付が変わった場合も、タブ再表示またはウィンドウ復帰時に更新します。前日の回答状態は新しい日付へ引き継ぎません。

総合結果では、回答順のレア度を絵文字グリッドとして表示し、問題文・選択肢・回答ラベルを含めない共有文面を生成します。共有時はWeb Share API、クリップボードコピー、X共有の順にフォールバックし、利用者が共有をキャンセルした場合は追加の画面を開きません。

5問を完了すると、日付、問題セット、合計点、称号、レア度の並びを同一ブラウザのプレイ履歴へ保存します。同じ日付の再プレイは当日分を上書きし、日付降順で最大30件を保持します。総合結果画面には現在の連続プレイ日数、最長連続プレイ日数、自己ベスト、四捨五入した平均点、直近7件の一覧とスコア推移を表示します。推移グラフは直近7件を古い日付から新しい日付へ並べ、最新スコアと前回プレイとの差も表示します。個人統計と推移は保存時と同じルールで日付を正規化し、同日データを二重集計しません。

総合結果では同じプレイ履歴から、日本時間の月曜〜日曜を1週間とするウィークリーチャレンジも計算します。現在週の月曜日から現在日までのデイリー結果だけを対象に、「3日プレイ」「UR・SSR・SRを合計6回答」「週間合計6,000点」の3目標を表示します。現在日より未来の履歴や練習モードの結果は加算せず、専用の保存データも作りません。月曜日になると新しい週として自動的に進捗が切り替わります。

`/practice`では、同一ブラウザのプレイ履歴に一度でも保存された現行問題セットだけを練習テーマとして解放します。同じテーマの履歴が複数あっても1件にまとめ、現行問題データに存在しない古い`questionSetId`は表示しません。練習では通常と同じ5問、回答後の分布、レア度、点数、称号を確認できますが、練習結果はデイリー進捗、プレイ履歴、連続日数、実績へ保存しません。未プレイテーマは練習モードから事前に閲覧できません。

`/collection`では、デイリーで発見したテーマをブラウザローカルへ保存します。保存対象は問題セットIDと初回発見日だけで、未発見テーマ名は表示しません。3・5・10・15テーマの到達バッジは保存せず発見データから毎回再計算し、初回発見や今回新たに解除したバッジだけを結果画面で通知します。詳しい運用は[テーマコレクション](docs/theme-collection.md)を確認してください。

同じ履歴から、初回プレイ、5日分プレイ、最長3日連続、UR獲得、3,000点到達、1日の全5問で多数派を避ける条件を対象とした6種類のローカル実績を計算します。解除済み件数と未解除条件の進捗を総合結果へ表示します。実績専用の保存データは作らず、履歴が更新されるたびに再計算します。

結果保存前後の実績状態を比較し、今回のプレイで未解除から解除済みに変わった実績がある場合だけ、結果パネルの先頭へ解除通知を表示します。同日再プレイは保存済みの当日結果との差分を使用し、既に解除済みの実績は再通知しません。履歴の読み込みまたは保存に失敗した場合は、誤通知を避けるため解除通知を表示しません。

プレイ履歴、実績、テーマコレクションは表示用のローカルデータであり、改変防止や達成の証明には利用できません。壊れた項目は読み込み時に除外し、保存に失敗しても当日のゲーム進行と共有は継続します。

壊れたデータ、過去日のデータ、当日の問題セットと不整合なデータは利用しません。既存問題セットIDは保存互換性に関わるため、公開後は不用意に変更しません。

別ブラウザ・別端末間の同期、厳密な重複回答防止、サーバー保存、管理画面は後続タスクです。
